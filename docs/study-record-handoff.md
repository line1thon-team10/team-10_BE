# 기록 정정 1단계 — FE 전달

대상 브랜치: `feat/study-record-contract`, 부모 `feat/focus-contract` / PR #11.
현재 운영 배포 `ebc7c3d`에는 이 문서의 새 기록 정정 구현이 포함되지 않는다.

## 달라진 동작

- `POST /api/records`, `PATCH /api/tasks/:id/record`가 demo/focus와 같은 사용자 잠금을 사용한다. 경합 시409 `REQUEST_IN_PROGRESS`를 반환하므로 기존 입력을 보존하고 다시 시도한다.
- 같은 기록에 이미 붙은 종료 세션을 다시 보내면 허용한다. 다른 기록에 소비된 세션은409 `SESSION_USED`를 유지한다. 기록 ID/최초 기록일은 바뀌지 않고 dayClose 박스는 중복 생성하지 않는다. 일반 toast까지 포함하는 동일 응답 재생은 아직 지원하지 않는다.
- 완료→부분/미완료 정정 시 기존 회독의 고정 기록 합집합과 당시 요구 범위를 다시 비교한다. 부족하면 자격을 무효화하고, 같은 기록들이 다시 충분해지면 기존 회차를 복구한다. 새 회차·퀴즈 결과·숙달도·과거 분모를 만들거나 덮어쓰지 않는다.
- `GET /api/books`의 `units[].round`는 유효 회독 수다. 유효 이력이 없으면 **0**을 반환한다. 순번1은 무효,2·3은 유효인 경우2를 반환한다. 부분 완료 블록은 기존대로doing이다.

## 충돌 판단

| 기존 차이 | 원인과 적용 기준 | FE 영향 |
|---|---|---|
| 같은 종료 세션 재전송에 SESSION_USED | BE가 같은 기록과 다른 기록을 구분하지 않음. study 명세에 맞게 수정 | 같은 본문으로 재시도 가능 |
| DB2 p.12–20 완료를 p.13으로 정정해도 회독 유지 | BE의 근거 재검사 누락. ERD의 recordIds/requiredRanges 고정 원칙 적용 | 정정 후 books 재조회 시 회독 수 감소, 복구 시 회복 |
| 미완료 단원도 기본1회독, 이력 최댓값이 회독 수 | FE 초안과 BE 문서 기본값1 및 BE max(pass_number)가 ERD의 유효 근거 원칙과 충돌. books 명세를0 이상 정수로 명확화 | books adapter의 `u.round ?? 1`은 서버0을 보존. 0회독 표시 허용 |

다른 완료 기록이 있어도 **기존 회독 스냅샷에 포함된 기록**만 재검사한다. 관계없는 새 기록은 자동 소비하지 않는다. 현재 생성되는 schemaVersion="1", requiredRanges=[[시작,끝],…]를 지원한다. 아직 생성 경로가 없는 명목 분량/알 수 없는 버전 스냅샷이 대상이면 서버 오류로 전체 정정을 롤백하며 임의로 자격을 변경하지 않는다.

## 다음 단계

복합 completedRanges와 조회 ranges, 엄격한 입력 모델, 일반 응답 멱등성, 신규 initial/remedial 회독 생성, 직접 재학습, 이월 블록 중복 제거, 마감 집계와 P1 23:30, 퀴즈 savedGrading은 이번 완료 범위가 아니다. API 명세 전체가 런타임에서 구현됐다고 해석하지 않는다.

검증: SQLite + PostgreSQL17에서 BE 전체425 passed / 1 skipped. 신규50개는 잠금 경합, 동일·타기록 세션 재사용, 완료→부분→완료, 범위 합집합/한 쪽 구멍/비연속 범위, 다른 단원·사용자 격리, 과거 요구 범위 유지, 저장 실패 롤백, 회독0과 이력 순번 구멍을 포함한다. 운영 배포 결과와 구분한 상세 기록은 [실행 계획](study-record-implementation-plan.md)에 있다.
