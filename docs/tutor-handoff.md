# 자료 기반 튜터 구현

T-01 POST /api/tutor는 새 질문(history 생략 또는 빈 배열)과 저장된 원문 한 쌍의 쉬운 설명만 지원한다. 위조 원문이나 타인 원문은 400 BAD_REQUEST이고 두 쌍 이상은 422다. 쉬운 설명의 question 응답은 저장된 원래 질문이다. 새 request.question은 쉬운 설명 요청의 표시 문구이며 새로운 주제나 근거 범위를 지정하지 않는다. parentId는 서버가 찾은 원문 ID다. 일반 문답과 쉬운 설명이 우연히 동일한 question/answer/pages를 가질 때는 동일 원문 요청으로 해석하며 자식의 자식을 만들지 않는다.

본인 자료의 현재 SHA 및 분석 버전에 맞는 완료 분석 텍스트를 사용하고, 분석 텍스트가 없으면 소유권이 검증된 원본 PDF의 네이티브 텍스트를 읽는다. 파일 SHA, 실제 페이지 수, 페이지 번호를 검증한다. 질문의 용어와 과목명을 기준으로 한 과목의 근거를 고른다. 여러 과목이 같은 순위로 모호하거나 읽을 근거가 없으면 503 AI_FAILED다. 서로 다른 PDF의 같은 페이지 번호는 모델용 임시 번호로 구분한 뒤 실제 materialId/page로 다시 매핑한다.

AI pin의 tutor 프롬프트를 재사용하되 기존 함수가 잘못된 페이지를 걸러 숨기거나 쉬운 설명의 원문 페이지를 강제로 덮어쓰기 전에 전송 응답을 검증한다. 실제 선택된 소유 자료의 페이지와 인용 원문만 저장하며 근거가 없는 답변을 성공으로 만들지 않는다. 의미상의 답변 품질은 실제 공급자 검증인 AI-02의 대상이며, 테스트용 전송 대체가 실제 AI 품질을 입증하지는 않는다.

`tutor_messages`와 `tutor_sources`에는 검증된 답변과 원문 인용만 저장한다. `ai_jobs`의 tutor/tutor_simplify 요청에는 입력, 자료 버전, 결과 identity, 실패 상태를 기록한다. AI 실행 중 DB 트랜잭션을 유지하지 않으며 최종 저장에서 소유권과 자료 버전을 다시 확인한다. 동일 입력의 최초 저장 메시지를 재사용하고 부모당 쉬운 설명은 한 개만 유지한다. 새 마이그레이션은 필요 없다.

T-02 GET /api/tutor/backup은 basic/easy별 최신 실패 입력만 사용한다. 같은 시각의 서로 다른 실패나 서로 다른 저장 후보는 모호한 것으로 거절한다. 사용자, 질문, 원문 ID, 자료 버전, 프롬프트/결과 버전이 일치하는 결과만 복구하며 외부 공급자를 호출하지 않는다. 최종 메시지 저장 직전에 실패한 경우 gateway가 이미 저장한 유일한 결과를 재검증해 복구할 수 있다. 이전 질문이나 임의 시연 답변으로 대체하지 않는다.

로컬 E2E는 실제 HTTP, 파일 업로드, DB, pinned prompt, gateway ProcessExecutor를 통과하며 유료 Groq 전송 경계만 fixture로 바꾼다. 실제 공급자 키와 답변 품질은 검사하지 않았다. 개발 중 CI 실행과 push는 하지 않았다.
