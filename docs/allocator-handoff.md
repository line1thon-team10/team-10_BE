# P-01 배치 엔진 인계

`app/services/allocator.py`의 `allocate(AllocationInput, max_search_nodes=250_000)`는 `allocation-v1`의 순수 계산 경계다. DB·외부 AI·현재 시각·endpoint·schema에 접근하지 않는다. P-02 및 재계획 호출자가 소유권, 준비된 자료, 네 칸 온보딩 확인, 사용자 현지 날짜와 입력 버전을 검증하고 결과를 preview에 저장한다.

## 입력과 결과

형식은 `app/domain/scheduling.py`의 frozen dataclass다. 입력 배열은 tuple로 복사하므로 호출 뒤 원래 list를 바꾸어도 계산 입력이 바뀌지 않는다. 잘못된 타입/숫자/참조/중복 ID/모호한 단원 범위는 `ValueError`다. 문자열 숫자나 bool을 수치로 변환하지 않는다.

| 입력 | 역할 |
|---|---|
| `Subject` | id, exam_date, target_score, exam_confirmed, goal_confirmed, minutes_per_page. 기준 속도 기본2.5이며 난이도 배수는 포함하지 않는다 |
| `UnitScope` | id, subject_id, material_id, sort_order, 현재 시험 범위 ranges, difficulty, mastery_score. 같은 단원 안 겹친 범위는 material union으로 정규화한다 |
| `WorkRequirement` | id, subject_id, kind=`remedial/review`, `ScopePart(unit_id, PageSpan)` 목록, 선택 not_before. ID별로 별개인 필수 의무다 |
| `BusyInterval` | 현지 day와 자정부터의 start/end 분. 일정은 호출자가 반복 회차를 펼치고 자정 경계를 나눠 전달한다 |
| `FixedTask` | 변경할 수 없는 started/completed 태스크의 기존 ID·과목·종류·날짜·시각·범위. FixedRange의 requirement_id는 별도 보충/복습 의무의 만족 근거를 연결한다 |
| `AllocationInput` | start_date, 위 subjects/units/busy/fixed/requirements. 기간은 마지막 시험일 전날까지다 |

새 학습 의무는 `UnitScope.ranges`에서 해당 과목의 fixed study 범위 합집합을 뺀 값으로 만든다. `WorkRequirement`로 같은 새 학습 범위를 다시 입력하지 않는다. 과목·단원별 원본 식별자를 보존하며 같은 material의 쪽 번호만 합친다. 같은 페이지의 개념 중복은 같은 단원의 배수를 한 번만 적용한다. 현재 목차의 서로 다른 단원이 같은 material 페이지를 소유하면 난이도를 추정하지 않고 거절한다.

`AllocationResult`는 `policy_version`, `feasible`, 새 `placements`, 그대로 보존한 `fixed`, `unplaced`, 한국어 `reasons`를 가진다. placements의 ID는 정책·과목·배치시각·실제 범위·속도 snapshot에서 결정적으로 생성된다. parts에는 requirement_id, unit_id, material별 PageSpan, 기준 속도, 난이도 배수를 담는다. 여러 단원이나 자료 조각을 같은 과목·종류의 태스크에 합쳐 짧은 잔여를 처리할 수 있으며 그 식별자는 지우지 않는다.

성공은 모든 필수 페이지가 정확히 한 번씩 배정되고 `unplaced=()`인 경우다. 새 학습과 보충에서 같은 페이지를 다시 공부하는 것은 서로 다른 의무이므로 각각 보존한다. 실패에서는 새로운 일부 배치를 승인 가능한 것처럼 반환하지 않고, fixed를 보존한 채 모든 남은 의무를 unplaced에 반환한다. 누락된 목표 확인은 `UNCONFIRMED_INPUT`, 고정 일정 충돌은 `FIXED_CONFLICT`, 완전 탐색으로 입증한 배정 불가는 `PLAN_INFEASIBLE` 사유다. HTTP 상태·응답 변환은 호출자의 책임이다.

## 정확한 시간과 가용 구간

시간과 점수 계산은 `Fraction`을 사용한다. `Decimal('100.00000000000000001')`를 float100으로, 작은 음수를 -0.0으로 바꾸어 통과시키지 않는다. float 입력은 그 값의 십진 문자열을 Fraction으로 옮긴다. `Placement.minutes`와 시작/끝은 반올림 전 분량이며 `display_minutes`만 HALF_UP 정수다.

가용 구간은 매일08:00~23:00에서 일정 합집합과 해당 날짜의 fixed 시간을 뺀 실제 연속 구간이다. 서로 떨어진10분 두 구간을20분 한 태스크로 합치지 않는다. 신규 태스크는 실제 예상 시간15~60분과 정수 페이지 경계를 동시에 만족한다. 표시가15분인14.999…분 태스크나 표시가60분인60.000…분 태스크를 허용하지 않는다. 큰 태스크를 먼저 잘랐을 때 잔여가15분 미만이면 앞 태스크의 경계를 바꾸는 경우도 탐색한다.

유효 분/p는 승인 기준 b × low1/mid1.2/high1.5/미측정1.2다. 예를 들어 high의 b=2.5는3.75분/p이며 두 번 보정하지 않는다. 출력의 기준 속도/난이도 snapshot을 이후 측정과 P4에서 보존해야 한다. 날짜·시각을 DB timestamp로 변환하는 해상도와 실제 preview 저장은 이 순수 엔진의 범위 밖이며, 호출자는 Fraction을 먼저 정수 분으로 잘라 배정 가능성을 다시 판단하면 안 된다.

## 배분 점수와 직전일 목표

점수는 `(확인된 목표/100) × 1/(시험일까지 일수) × 아직 배치하지 않은 고유 새 학습 페이지 × (1-숙달도)`다. 숙달도는 측정된 현재 단원만 현재 시험 범위 고유 페이지 수로 가중 평균한다. 측정이 없으면 계산용0이며 원본 null은 바꾸지 않는다. 점수0인 과목도 필수 범위를 유지한다. 모든 점수가0이면 시험일·과목 ID 순으로 우선한다.

시험일 내림차순으로 예약일을 처리하고 같은 시험일 과목은 하나의80% 그룹이다. D-1이 다른 시험일이면 D-2를 쓴다. 예약일이 겹치면 먼저 처리한 늦은 시험 그룹만80% 대상이며 앞 시험 그룹은 나머지20%에 포함된다. 시험 당일 이후에는 해당 과목을 배정하지 않는다.

이번 P-01에서 오케스트레이터가 확정한 목표의 정확한 의미는 다음과 같다. C는 그날 일정 차감 후 총 공부 가능 시간이며, 이미 시작·완료한 고정 태스크도 그날 배정량에 포함한다.

1. 먼저 focus0.8C/other0.2C로 목표를 만든다.
2. 각 그룹의 고정량+아직 배치하지 않은 실제 잔량으로 목표를 제한한다.
3. 한 그룹이 덜 필요하면 남는 용량을 다른 그룹의 실제 잔량에 이전한다. 총 잔량<C이면 남는 시간은 비운다.
4. 전체 필수 범위가 들어가는 배치 중, 예약일의 역순 우선권대로 이 목표와 실제 그룹 분량의 L1 차이 합을 최소화한다. 그룹 안의 상대 배분은 점수와 잔량으로 만든 목표를 사용한다. 최종 동점은 시험일·과목·자료·단원 순서·시작 페이지·의무 식별자로 결정한다.

C100/A40/B60이면 목표는40/60이다. A40/B15만 배정해 표면적인 비율을 더80/20에 가깝게 만들지 않는다. A가 이미 고정80분이고 실제 남은 슬롯이20분이면 B20분을 우선한다. 고정 태스크와 정수 페이지/연속 구간 때문에 목표에서 벗어나야 하면 실제 차이를 `RESERVATION_DEVIATION` 사유로 반환하고 고정 태스크는 이동하지 않는다. 다른 필수 범위의 완료 가능성이 목표 비율보다 먼저다.

예약일 이후 남은 일반 날짜는 날짜 오름차순으로 같은 과목 점수·잔량 목표를 적용한다. 새학습 페이지의 물리 범위는 최종 날짜순으로 조립하므로 예약일을 역순 계산했다는 이유로 같은 단원 범위의 뒤쪽을 앞쪽보다 먼저 소모하지 않는다.

## 고정 태스크와 보충 의무

fixed 객체의 ID·시간·범위·상태를 그대로 결과에 포함한다. 과거 완료 태스크는 새 학습 필요 범위에서만 빼고 미래의 시간 용량을 차감하지 않는다. 해당 날짜의 고정 태스크가 새로운 일정과 겹치거나 시험일/공부 가능 시간 밖에 있으면 조용히 이동시키지 않고 실패 사유를 반환한다.

완료된 study가 보충 의무와 같은 페이지라는 이유로 WorkRequirement를 지우지 않는다. 보충/복습을 만족시키는 고정 근거는 같은 과목·종류·requirement_id일 때만 소비한다. 보충 의무가 들어갈 자리가 없으면 그 의무를 unplaced에 남긴다. fixed의 페이지 없는 ranges도 보존한다.

현재 **신규 배치는 페이지 근거가 있는 범위만 지원**한다. 페이지 없는 명목 시간 태스크의 신규 생성/분할 인터페이스는 확정되지 않은 후속 범위다. 빈 ScopePart 목록으로 작업을 몰래 없애지 않도록 새 WorkRequirement의 빈 ranges는 거절한다. 이미 완료·시작한 페이지 없는 태스크 보존은 지원한다.

## 탐색의 의미와 한계

엔진은 먼저 전체 범위의 정확한 배치 가능성을 확인한다. 한 태스크에는 같은 과목·종류의 모든 정수 페이지 조합을 고려할 수 있으며15~60분에 맞는 조합을 실제 슬롯에 왼쪽부터 놓는다. 같은 단원·의무의 페이지는 동일한 속도·시험일·시작 가능일을 가지므로 페이지마다 객체를 만드는 대신 범위와 남은 개수로 탐색한다. 메모화와 총시간·시험일별 하한 검사를 사용한다.

예약일마다 목표 차이의 admissible 하한을 사용한 탐색으로 배정량을 순서대로 검사한다. 후보는 그날 실제 구간에 들어가면서 나머지 모든 날짜도 완성할 수 있을 때만 선택된다. 따라서 큰 것부터 놓는 탐욕 배치가 실패했다는 이유로 불가능을 반환하지 않는다. 최종 범위는 R-01 구간 연산으로 조립하며 큰 PDF의 전체 쪽 set을 만들지 않는다.

문제 자체는 조합 탐색이므로 최악의 실행량은 지수적이다. 기본 `max_search_nodes=250_000`은 계산 예산이며 제품의 페이지 수 제한이 아니다. 예산이나 Python 호출 스택 경계에 도달하면 별도 `SearchLimit` 예외가 발생한다. **SearchLimit을 PLAN_INFEASIBLE로 바꾸거나 부분 결과를 승인하면 안 된다.** 호출자가 더 큰 예산으로 재시도하거나 후속 계산 경로를 정해야 한다. 공개 API의 시간 예산·취소 연결은 아직 하지 않았다.

## 검증과 측정

`tests/test_allocator.py`는68개 테스트를 포함한다. 정상/0시간/15·60분/짧은 잔여/연속 구간/자료 union/미확인 목표/난이도/시험일/예약 충돌/반올림/보충 보존/고정 상태/입력 순서 독립성을 검사한다. 100개의 작은 사례는 개별 페이지의 모든 부분집합을 태스크로 만드는 독립 완전탐색 오라클과 feasibility를 비교한다. 별도 사례는 예약일의 가능한 페이지 배정을 모두 열거하여 최소 L1 차이를 비교한다.

`6bfb203` 코드에서 로컬 측정한 결과:
