# 집중 모드 계약 보정 계획

부모: `feat/demo-package` / PR #9. 이번 단계는 집중 API와 이를 보호하는 저장 규칙이다. 학습 기록·퀴즈 전체 계약 보정은 별도 단계로 유지한다. Astra-max는 PR #9 immutable HEAD를 읽기 전용으로 검토한다.

## 기준과 발견한 차이

- FE 경로/응답을 유지하고 `docs/api/focus.md`, `study.md`의 확정 계약을 구현한다.
- 기존 BE의 반복 pause 오류, 일반 resume의 확인 기준 초기화, 미래/과거 태스크 시작, 날짜 라벨만 사용하는 시간 합계, material의 가짜 null-id 객체, task.ranges 누락을 수정한다.
- ERD 메모의 '활성 세션 중 seed 거절'은 승인된 42분 reset 시연 및 이미 구현한 demo 계약과 충돌한다. **reset/seed는 사용자 잠금 아래 원자 교체 허용, next-day만 SESSION_RUNNING**으로 문서 정정한다.
- 일반 사용자의 todayMinutes는 현지 자정 경계로 구간을 잘라 합산한다. 데모 사용자는 실제 측정 시계와 가상 날짜가 다르므로 study_date에 귀속한다. 오래된 세션 조회 중에도 오늘 총/과목 총에는 실제 같은 사용자 세션들을 집계한다.
- 자동 종료 확인 기한은 순공부 초 기준이다. 일반 resume/pause 재전송은 기한을 연장하지 않는다. 확인 대기 중 resume 또는 pause만 현재 순공부 시간을 새 확인 기준으로 삼는다. 모든 동작은 같은 요청 시각 하나를 사용한다.

## 원자 단위와 검증

1. 공통 사용자 잠금을 별도 모듈로 추출한다. demo와 focus가 동일 행 잠금을 사용하고 reset/날짜 이동과 경쟁하지 않게 한다.
2. focus migration: 사용자당 running/paused 최대 하나, 세션당 열린 구간 최대 하나. 시작 당시 예상 시간·문구를 저장한다. 기존 중복 데이터는 삭제/임의 정리 없이 migration을 거절한다. 업/다운그레이드와 SQLite/PostgreSQL 제약을 검증한다.
3. 집중 상태 전이: 소유권·오늘·활성 과목/계획 검사, 같은 task 재시작, 반복 pause/resume/end, 2배+10분 경계, 지연 조회 자동 종료를 검증한다. 읽기도 자동 종료 쓰기가 가능하므로 동일 잠금을 사용한다.
4. 집중 조회: 구간별 순공부/멈춤 시간과 현지 날짜 교집합, 사용자별·과목별 합계, 복합 범위/자료 없음·보관 과목의 과거 세션을 검증한다.
5. UUID/본문 요청 모델과 응답 모델을 연결한다. 부정확한 입력을 500으로 보내지 않고 422/404/409로 계약화한다.
6. 동시 시작·resume/end·reset/next-day 경합, 롤백, 42분 시드 호환을 실제 PostgreSQL과 SQLite에서 검증한다. 문서 검사와 기능 테스트 결과는 구분한다.

각 단위 완성 시 즉시 커밋한다. 최종 stacked PR에는 FE/BE/ERD 차이와 수정 근거, migration 사전 조건 및 미배포 상태를 명시한다. 이번 작업에서 운영 DB/서버를 바꾸지 않는다.
